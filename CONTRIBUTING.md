# Contributing to Lattice

Keep contributions focused on passive packet analysis, explainable rules, local persistence, and the existing command-line and Streamlit workflows. Open an issue or discussion before introducing a new dependency, storage format, or detection category.

## Development setup

Create a virtual environment and install the repository requirements:

```bash
python -m venv .venv
```

Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Linux or macOS:

```bash
source .venv/bin/activate
python -m pip install -r requirements.txt
```

No network capture is needed for the normal test suite.

## Before submitting a change

Run:

```bash
python -m pytest
python -m compileall -q lattice scripts tests app.py
python -m pip check
```

Also run `git diff --check` and review the diff for generated databases, capture files, caches, credentials, and local paths. The repository ignores common SQLite and cache artifacts; do not force-add them.

When behavior changes, add a focused regression test. Relevant test areas include:

- parsing and capture formats in `tests/test_parser.py`;
- windows and counters in `tests/test_features.py`;
- detection semantics in `tests/test_detector.py`;
- persistence and querying in `tests/test_storage.py`;
- full replay workflows in `tests/test_pipeline.py` and `tests/test_end_to_end.py`;
- cross-component audit regressions in `tests/test_reliability.py`;
- live lifecycle behavior with a fake backend in `tests/test_live.py`; and
- dashboard calculations and headless workflows in `tests/test_dashboard.py`.

The environment-gated real-sniffer test is not part of routine verification. Never start live capture on a contributor's behalf or against a network without explicit authorization.

## Documentation expectations

Update the document that owns the affected behavior:

- [README](README.md) for installation, first use, top-level capabilities, or
  project-wide limitations;
- [user guide](docs/user-guide.md) for CLI syntax, dashboard controls, and
  operator workflows;
- [technical reference](docs/technical-reference.md) for processing semantics,
  configuration, rules, storage, and data limits; or
- [troubleshooting](docs/troubleshooting.md) for failure diagnosis and manual
  host validation.

Keep cross-links synchronized when adding a new guide. Examples must be
copy-pastable and must not claim that a threshold event confirms an attack.

Checked-in evaluation output is generated by:

```bash
python -m scripts.evaluate
```

Regenerate it only when the evaluation inputs, implementation, or intended evidence change. Packet and event counts are deterministic for the recorded seed; elapsed time and throughput are machine-dependent.

## Scope and data handling

- Preserve the shared offline/live pipeline unless a change requires otherwise.
- Prefer deterministic tests and synthetic captures over real traffic.
- Do not commit private captures, generated databases, or exported network metadata.
- Keep packet payloads out of persistence and diagnostics.
- Document false-positive and false-negative limitations for new rule behavior.
